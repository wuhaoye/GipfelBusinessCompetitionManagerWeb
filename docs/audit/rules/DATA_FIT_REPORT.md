### 1.2 解析算法

1. 用 `ws.merged_cells.ranges` 把列 A 的合并区域展开成 `行号 → 分组首字母`（普通模式，不用 `read_only`）；
2. 行 3 起逐行：**列 B 为空且 C..G 有名字** = 表头行（记下各列目的地）；**列 B 非空** = 数值行（B 是出发地，
   C..G 是按列号与表头行一一对应的距离）；
3. 用「表头行 + 紧随其后的数值行」配对产出有向边 `(出发地, 到达地, 距离)`。

### 1.4 系统今天能不能装下这份里程表？——逐项对照

目标模型：`apps/maps/models.py`（`MapNode`/`MapEdge`/`MapNodeType`/`PathType`）+ `sheet_spec.py`
的「地图节点」「地图连线」「路径类型」表 + `builder`（`core.py:610 node` / `core.py:642 edge`）。

| 里程表提供 | 系统目标字段 | 目标是否必填 | 今天能否表示 | 缺什么 |
|---|---|---|---|---|
| 节点名 × 47 | `MapNode.name` | 必填 | **能** | — |
| 分组首字母 19 个（A/B/C/…） | 无对应字段 | — | **不能** | 系统没有「首字母/分组」概念，只能丢弃（仅作分组提示） |
| 节点类型 | `MapNode.node_type`（FK，必填） | 必填 | **不能** | 4 份工作簿中「地图节点类型」**0 行**；`builder.node()` 要求先 `node_type(...)`，否则 `BuilderError` |
| 节点坐标 | `MapNode.x` / `MapNode.y`（FloatField，默认 0） | 非必填 | **形式能，语义不能** | **47×2 = 94 个坐标值全部缺失**；只能全写 0 → 47 个节点全部堆在画布原点，地图不可用 |
| 所属区域 | `MapNode.region`（文本） | 可空 | **形式能，语义不能** | 「区域」表 **0 行**；47 个节点的 region 只能留空，区域总览无从聚合 |

| 路径类型 | `MapEdge.path_type`（FK，必填） | 必填 | **不能** | 4 份工作簿中「路径类型」**0 行**；**148/148 条连线缺 path_type**，而载具按 path_type 判断可通行性 → 即便强导也让全部载具无法通行 |

**量化结论**：里程表能提供 `地图节点` 的 **47/47 个名字**、`地图连线` 的 **148/148 个 (起,终,距离) 三元组**；
但 3 个必填元数据 **0 来源**（节点类型 0 行、路径类型 0 行、节点坐标 94 值缺 94），1 个语义字段
（区域）0 来源。**今天的建包链路一行也导不进去**；要落库必须由转换脚本**编造**至少
`1 个节点类型 + 1 个路径类型 + 47 组坐标`（R4 实测，见 §3.2）。

**两条必须点名的语义问题**

1. **`H bonus` 与 `幸福指数` 的幸福度二义**：民生表同时有 `幸福指数`（15、117、…、49790）和 `H bonus`
   （1.3、2.8、…、17.7）；系统只有一个 `happiness_index_bonus`（规范中文表头「幸福度加成」）。
   哪种解释都自洽（`H bonus` 读作 happiness bonus 更像「幸福度加成」，但那样 `幸福指数` 22 个值无家可归），
   报告只能并列两列原值，**必须由出题方裁定**——这正是「一个字段、两列数据」的静默丢数据风险点。
2. **两段的价格语义不一致**：民生段是 `价格`（唯一价格列，1000–50,000,000），产业段是
   `建造价格（元）`（8,000–5,000,000）**加** `启用价格`（9,860–5,938,000）。系统的 `price` +
   `activation_price` 与产业段天然对齐，与民生段则只能把「价格」塞进 `price`、`activation_price` 留 0。
