> **对象**：`GipfelBusinessCompetitionManagerWeb`（Django 5 + DRF + daphne + Socket.IO / Vue 3 + TS + Element Plus）
> **问题**：赛事规则书（Update 1.0 / 2.0 / 3.0 + 配套 xlsx 指标表）逐条规则，系统是**已实现 / 部分实现 / 未实现 / 实现与规则不一致**？
> **范围界定**：本报告只做**规则覆盖度与业务逻辑完整性**判断，不重复 [`分支代码缺陷审计报告.md`](../分支代码缺陷审计报告.md) 已归档的 366 条通用代码缺陷；仅当某条规则**因**这些缺陷而无法落地时才引用。

### 0.2 一句话结论

系统本质上是一个**「通用主数据 + 可编程合同引擎 + 股票引擎」的赛事平台**，而**不是规则书的实现**。
规则书中真正被"实现"的部分集中在两处：**股票撮合/K 线/持仓（v1 第三部分）** 与 **物流里程-运费-碳排计价（合同效果）**；
而**公司全生命周期的资金与权益类规则（拍卖、选址、注册、贷款、股权、评分）几乎整体缺失**——这些规则在规则书里占了 Update 1.0 前 9 页与 Update 3.0 的 P6–P23。

### 0.3 架构性根因（解释"为什么大面积未实现"）

| 根因 | 证据 | 后果 |
| --- | --- | --- |
| **无"公司资产/权益"实体**：`Warehouse`/`ProductionLine`/`Vehicle`/`Material`/`Part`/`Product` 均为**比赛级主数据**，没有任何指向 `Company` 的外键，也没有"归属/购置/持有量"表 | `backend/apps/warehouses/models.py:7-36`、`backend/apps/production_lines/models.py:7-29`、`backend/apps/vehicles/models.py:13-44` | 规则中一切"购置/持仓/额度/抵押/折旧"都无处落地；业务只能通过**改写产业卡片上的数字字段**近似表达 |
| **无"区域经济指标"实体**：`Region` 只有名字 + 概览卡片 JSON，无幸福度/人口/就业率字段 | `backend/apps/regions/models.py:5-26` | 幸福度↔人口↔就业率↔碳排的联动系统**没有数据载体** |

### 1.4 判定与证据强度标记

- **判定**：`已实现`（规则要点全部有代码与运行时约束）/ `部分实现`（有数据模型或可编程能力，但缺强制/流程/契约）/ `未实现` / `实现与规则不一致`（有实现但与规则条文或算例冲突）
- **证据强度**：
  - 【已读码】= 我逐行读过该文件的相关区段
